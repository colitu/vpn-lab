# Colitu VPN Lab

**Воспроизводимые тесты VPN-протоколов в намеренно испорченной сети.**

Это тестовая лаборатория серии *«Выдержит ли?»* (*Can It Survive?*) на YouTube-канале Colitu. Мы берём два Linux-сервера, поднимаем между ними четыре VPN-протокола, специально ухудшаем сеть (потеря пакетов, задержка, ограничение скорости) и измеряем, что продолжает работать.

Каждая цифра из наших видео получена этими скриптами. Их можно прочитать, проверить и запустить самостоятельно. Подробное описание: [README.md](README.md) (на английском).

## Коротко

- **Протоколы:** WireGuard, OpenVPN (UDP), VLESS + Reality, Hysteria2 и для сравнения соединение без VPN.
- **Плохая сеть:** Linux `tc netem` на клиенте. Одинаковые потери **в обе стороны**, +20 мс задержки в каждую сторону, лимит 100 Мбит/с. Затрагивается только трафик к тестовому серверу.
- **Уровни потерь:** 0 %, 1 %, 5 %, 10 % (в каждую сторону; 5 % в обе стороны ≈ 10 % туда-обратно).
- **Измерения:** для каждого уровня и протокола по 3 прогона в случайном порядке:
  - скорость загрузки файла 64 МБ
  - время загрузки двадцати «страниц» по 100 КБ и число неудачных

## Запустить самому

```bash
# на тестовом сервере
sudo bash lab-server.sh <ip_клиента>        # как обычный сайт: sudo LAB_CC=cubic bash lab-server.sh <ip_клиента>
# скопируйте client-bundle.tgz на клиент, затем на клиенте:
sudo bash lab-client.sh
sudo bash /opt/colitu-lab/lab-run.sh mytest "0 1 5 10" 3
python3 analyze.py /opt/colitu-lab/results/mytest.jsonl summary.json
# очистка
sudo bash lab-teardown.sh client            # на сервере: sudo bash lab-teardown.sh server <ip_клиента>
```

## Прежде чем цитировать цифры

- **Алгоритм управления перегрузкой TCP сильно влияет на результат.** Внутри WireGuard и OpenVPN вашим TCP управляет сервер сайта. BBR устойчив к потерям, а CUBIC (по умолчанию в Linux) при потерях заметно замедляется. Поэтому мы измеряем оба варианта и публикуем оба.
- **Потери случайные.** В реальных Wi-Fi и мобильных сетях они часто идут пачками, и это может изменить расстановку.
- **Один маршрут, одна пара серверов.** Абсолютные цифры в другой конфигурации будут другими. Сравнивайте протоколы внутри одного прогона.
- **Это не тест на блокировки.** Что происходит, когда UDP заблокирован, мы разбираем в отдельном выпуске.
